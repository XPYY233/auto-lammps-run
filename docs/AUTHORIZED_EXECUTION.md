# 从候选方案到已有许可下的执行

Issue #41 将 `CandidateExecution` 接到原有候选记录、账本、受限上传、一次性提交及
`FollowingService`。受信控制器可从一个已准备的普通科研任务，推进到已保存分析报告。
同一个候选使用确定的尝试键，刷新或重启不能改名重新计算。

此阶段是后台连接代码，尚未开放网页提交按钮或部署真实执行。用户不需要自行写
LAMMPS 输入；受信部署、科学检查及许可签发应由独立控制端落实。代码没有替这些环节
创建批准，也没有用准备完成、签名正确或摘要格式正确证明科学检查通过。

## 请求与许可的关联

1. 从当前冻结条件和持久候选记录读取输入，不接受浏览器指定任意文件路径或提交键。
   条件摘要、生成记录中保存的条件身份、生成上下文摘要、模型请求身份和输入快照必须
   一致。实际字节再次核验；论文模式和参考来源输入仍受原有发布/隔离门限制。
2. 使用已注册的评测，要求角色为 `agent` 且任务身份等于该普通研究的冻结条件摘要。
   评测由控制端预先注册，不在此服务中创建。该任务身份与 manifest 中的生成上下文摘要
   用途不同，后者由执行许可精确绑定；二者不能混用。
3. 按原始资源预留并渲染确定的资源脚本。默认只支持单进程；显式提供与授权摘要相同的私人
   `runtime_profile_path` 后，按声明的单节点 MPI 容量核对（最多 8 个进程）。时间必须整分钟、
   内存必须整 MiB；不兼容时拒绝，不偷偷缩小请求。准备计划不会上传、派发或调用模型。
4. `ExistingAuthorization` 读取私人控制目录中已经签发的许可、密钥及已批准资源脚本，
   验证签名、到期时间、请求、输入、资源、输出、软件、运行配置、已审查提交和固定的
   批准/评分/静态检查身份。脚本字节必须与本次确定渲染的脚本相同。
5. 许可通过后进行一次受限上传；上传后再次核验有效期及全部绑定，再将许可内容、资源
   脚本和固定策略的摘要写入不可替换的账本事件，之后才由提交服务抢占派发。
   许可内容摘要与计算节点执行意图使用相同定义，不公开密钥或许可正文。
6. 已经派发的请求只进入原有跟进服务，过期许可不妨碍核对已存在的作业。未知提交按原
   请求核对；不再次上传、派发或生成新尝试。上传结果不明保留为待核对，不自动重传。

上传、提交、资源脚本与回收须配置同一登录入口、解释器和请求根目录；资源脚本启动器
必须与回收端固定的 runtime helper 一致。远端仍独立核验其安装的配置、许可和文件。
本地许可镜像不证明远端已经安装相同许可或完成身份隔离。

## 后台接口

受信部署组装 `CandidateExecution(tasks, ledger, snapshots, staging, submission, following,
authorization, environment, runtime_profile_path=...)`，其中工具与路径来自管理员配置，不来自生成模型。
不提供运行配置镜像时保留单进程限制；提供时每次准备都重新校验其摘要与授权固定值一致。

- `prepare(task_id, evaluation)` 返回已预留请求、确定输入及资源脚本，供控制端核验。
- `advance(task_id, evaluation)` 在具备许可时完成上传/一次派发并执行一次后台跟进。
- `run(task_id, evaluation, stop=..., notify=...)` 继续跟进至分析完成或待核对。
  停止不取消已有 HPC 作业；科学状态仍为未核验。

当前没有自动签发/安装许可、真实代码审查或科学检查服务。固定身份必须来自受信的
已核验部署，不能让 Agent 填入任意摘要冒充批准。密钥和镜像控制目录不得对主 Agent
开放。正式权限隔离、源代码隐藏与真实部署继续是未完成验收。

候选记录只支持第一版方案，尚未增加一次修复的候选版本管理。本服务不能通过创建新
评测绕过两次上限；后续修复必须保留同一评测和完整历史。文献测试的无答案任务发布、
作者参考端连接、真实模型/计算、OVITO 和独立评分仍需继续完成。

## 验证边界

测试实际调用合成响应下的候选生成、ASE 几何准备、势函数绑定、输入冻结、账本、文件
接收程序、远端提交辅助程序的许可/脚本检查、本地子进程字节回收以及数值分析。外部
模型响应、调度器和网络由合成数据替代；生成的 LAMMPS 文本从未执行。目标输出为手工
给定的合成数值，只证明软件连接和约束，不能证明 Agent 的物理方案正确或科学复现。

覆盖缺许可、错误批准身份/资源/输出/脚本、上传时过期、上传未知不重传、派发未知不重提、
任务身份与角色不符、输入变化、提交前取消、完成后许可过期仍可读取状态，以及不可替换的
授权摘要。重复执行完整合成链路保持一次模型替身调用、一次派发和一次下载。

## 网页与持久执行队列（Issue #95）

网页新增任务级 execution 状态与发起入口，仅接受当前任务版本。ExecutionJobs 将已准备
候选绑定到控制端指定的既有评测，保存不可变意图及追加历史；浏览器不能指定评测、路径、
许可或尝试键。队列复用 CandidateExecution 的许可核验、一次性上传/提交和 FollowingService。
重复点击沿用同一队列记录和请求；进程中断后按账本恢复，提交已发生时只对账。
跨进程文件锁保护同一队列步骤。部署身份变化、许可缺失或检查异常保存待核对，不自动重试。
这些状态不会通过重新点击或重启被清除；后续受信恢复界面尚未实现。

网页服务的后台线程持续推进任务，关闭浏览器不影响执行。服务自身停止时暂停跟进；监督
服务重启后扫描原队列。worker_alive 来自当前线程存活检查，不从“运行中”字符串推断。
网页进程不应运行在休眠电脑上作为长期集群服务；停止它不取消远端作业。

使用 `--execution-config` 加载 Git 外、仅本人可读的部署配置，同时指定已有 `--ledger`。
配置精确字段为：snapshots_directory、collections_directory、reports_directory、audit_directory、
stage_endpoint、submit_endpoint、collect_endpoint、environment、authorization、runtime_profile_path、
max_polls、interval_seconds、query_max_bytes、task_evaluations。
三个 endpoint 沿用 StageEndpoint；environment 沿用 BatchEnvironment；authorization 为
ExistingAuthorization 的 directory 和固定 pins；task_evaluations 是控制端给出的任务 ID 到
既有评测 ID 映射。装载不签发许可、不请求远端；状态读取不预留计算或提交。结果读取和
原始下载自动共享同一账本和产物目录，拒绝不一致的候选目录或结果配置。

此入口仅补上“已准备且已绑定部署的方案到结果”。科学条件自动整理/确认、自动许可
签发与安装、用户自定义 HPC 连接的能力发现和执行部署、第二版修复候选仍未完成；不能
将本入口或合成全链路验收宣称为普通用户从空白需求到科学结果的完整自动化。

## 保存的 HPC 连接参与执行（Issue #97）

上述私有部署配置可增加 hpc_connection_revision（正整数），显式选择网页保存的连接版本。
四个既有适配器共享此版本的地址、端口、用户名和私有认证；不再从 SSH 别名推断真实目的地。
requests root 必须位于该版本的工作目录内，分区/账户必须与已核验部署相符。
装载配置不连接远端、不安装程序或签发许可。未填写该字段保留原部署入口。

首次准备在现有账本追加不可变连接摘要及版本。修改网页设置产生新版本；已有队列、
查询和回收仍使用原版本。恢复时更换部署连接会停在“执行需要核对”，不会转投新集群；
已上传/派发的旧别名请求不能被新连接认领。连接文件修改也会在网络调用前被拒绝。
远程命令仍由原适配器固定生成，浏览器/模型不能给出任意命令。

目前是将已有核验部署接到用户保存的连接。自动环境发现、安装受信工具、任务授权和
多连接任务调度尚待后续实现；仅保存地址或 SSH 成功不能显示“可以自动计算”。
运行中的首篇 B 继续原部署，不切换到本版本。

## 新科研任务自动登记（Issue #99）

私有 execution 配置可增加 research_enrollment：campaign、system_sha256、policy_sha256。
campaign 必须是已经批准且登记的账本批次；policy_sha256 是当前策略 canonical JSON 的
SHA-256。配置只选择既有政策，不创建/扩大额度。task_evaluations 可为空，仍支持原固定
映射供已有任务恢复。控制端保存的系统身份不能由浏览器或模型指定。

网页请求生成方案时，先核对已冻结的用户科研条件，在原账本登记 agent 角色、repetition=0、
最多两次，然后启动原候选流程。task→evaluation 绑定追加保存，重启、重复点击及并发
不会换身份。已生成但未预登记的候选不事后自动纳入；复现资料仍走独立释放/隔离入口。
政策或系统变更不能覆盖旧绑定。状态查询不登记任务、不预留计算或调用模型。

此步消除新任务逐项手写 evaluation 映射，不签发运行许可。HTTP 串联验证中模型与调度
为合成替身，签名执行许可仍由显式测试夹具提供；因此尚不代表从空白需求到真实科学结果
已经自动化。下一缺口是依照真实核验的部署和科学检查证据自动准备并安装任务许可。

## 原生 Slurm 科研部署（Issue #101）

用户已运行验证的集群原生 MPI 启动方式可接入同一候选、上传、记账、一次提交、回收
和分析链路。默认仍是原隔离部署；失败时绝不自动退回原生模式。此实现未升级正在运行
的开发评测，也不改变原有输入、两次提交上限或历史。

管理员在候选配置固定 `output_layout: working_directory`，模型按相对文件名生成输出，
此布局进入模型请求身份和输入快照。默认 `isolated` 保留原 `/output/` 协议。生成后不
替换脚本中的字符串，不把已冻结隔离脚本改写为原生脚本。输出与输入文件/目录冲突时
拒绝；执行前核对布局与固定部署一致。

相同 `runtime.json` 可明确设 `execution_mode: native_slurm`，附 `native_slurm` 对象：

- `scope: trusted_research`、`formal_isolation: false`、
  `storage_enforcement: collection_bound_only`，必须显式承认本模式边界。
- `max_ranks` 固定管理员核实的单节点容量；实际 CPU 集、内存 cgroup、Slurm 任务身份、
  节点、资源和剩余时间仍独立核验。用户输入不能扩大配置的容量。
- `shell_path`、`bootstrap_path`、`mpi_path`、`engine_path` 使用已核实的绝对路径，
  `files` 将这些文件及选择纳入的环境依赖逐一绑定 SHA-256；`modules` 固定模块列表。
  不从模型输出取得这些值，也不因增加本模式下载或重新编译引擎。
- 原 requests/control/runtime 三目录边界、scontrol 摘要及上传/签名身份约束保留。
  此模式不装载输出 FUSE 卷，不复用隔离模式的 fork/loopback MPI 参数。

已有执行许可还必须明确 `execution_scope: trusted_research` 和 `formal_isolation: false`；
签名同时固定完整部署摘要。仅填 native_slurm 名称不构成许可。启动器使用集群环境初始化、
固定模块及 `mpirun -np <已分配核数>`，设置 scheduler bootstrap；一次性执行意图先落盘，
普通文件副本保持原始输入字节，工作目录的输出直接进入原有回收格式。失败/超时保留
退出码和诊断，调度完成与科学通过仍分开。

**边界**：原生模式依赖受信科研部署，未提供进程文件系统/网络隔离，不能用于声称
强制源码不可达的正式盲测。程序/模块入口摘要也不证明所有动态依赖均被隔离或固定。
CPU/内存/时间依赖已核验集群控制；storage_bytes 在该模式中仅作为回收大小边界，
不是整个文件系统硬配额。需要磁盘硬配额或不受信多租户时，部署方必须先补齐相应
隔离/配额，不能从此实现推导已有保障。生成模型仍没有 SSH/终端权限。

当前完成合成模型/调度/目标输出的文件链路验证，未完成该新版真实集群部署、自动签发
与远端安装许可、独立 API 自动计算验收；这些是后续工作，不能要求普通用户逐任务
填写签名或路径。正式 API 配置仍需本项目密钥。

## 已批准部署下的自动许可交付（Issue #103）

私有执行配置可选 `authorization_mode: automatic`；省略时仍读取已有许可，不改变旧任务。
自动模式的 `authorization` 提供私人目录及已经批准的 profile/reviewed_commit/approval/
scoring/software 身份，另设 `max_atoms` 和 `lifetime_seconds`。这些批准/审查证据由受信
部署提供，代码不会生成虚构的审批记录；控制端与远端的一次性私有签名密钥部署仍须
完成。模型和浏览器不能提交这些字段、读取密钥或调用签名器。

后台在已有两次限制的普通科研评测、冻结候选和唯一请求下重算静态检查，核对输入脚本
与原结构/势函数适配命令和模型工作流一致，确认输出分析格式受支持并保持原实现身份。
检查报告摘要进入许可，批准范围内自动签名、保存并交付。报告明确
`static_input_contract_only`，不是物理正确性、科学通过或独立审查的证明。

同一请求的 envelope、batch 和报告先在私人 bundle 固定，只写一次；恢复时读取已有
字节，不能刷新到期时间或改名重置次数。远端安装器验证签名、运行配置与 batch 摘要，
先写脚本、最后写许可，以许可作为完成标志；相同内容可补齐，冲突内容拒绝覆盖。
安装器没有调度调用。安装回执未确认时不上传目标输入、不派发作业；后台每至少一分钟
最多补交三次相同内容，之后进入待核对。交付重试不是计算重试，真实派发仍由原账本
单独计数。过期、部署变化或未知计算提交沿原恢复流程处理，不自动重新签发/重提。

保存的 HPC 连接同时用于许可交付，必须与上传、提交、查询、回收的连接版本相同。
私有审计保存交付摘要、回执和失败，账本保留每次交付意图；密钥不传输、不记录到
命令参数，许可正文不回传到网页或公开 CI。

合成验收覆盖原隔离和原生两种配置，从空的逐任务许可目录经安装、派发、回收到分析，
不再由测试人工写入任务许可。基础部署/密钥仍由夹具提供，外部模型和调度/物理结果
均为合成；真实新版部署、密钥初始化、运行模型 API 及端到端科研验收仍未完成。


## 一次启动研究流程

启用自动许可、候选服务与同一执行队列的部署提供 `POST /api/tasks/{id}/workflow`，
请求仅包含当前冻结条件的 revision。操作保存持续流程意图，后台登记身份、生成
候选、静态核对、交接既有执行服务。浏览器不写许可、请求 ID 或提交上限。
GET 只读和服务启动不会为未明确启动的旧任务授权计算。未知模型请求、配置变化和
科学缺项保留历史并等待处理；不自动重复模型调用或重置评测。该入口从已冻结条件
开始，尚不等于自然语言条件整理、一次修复及完整科研验收均已完成。

# 从候选方案到已有许可下的执行

Issue #41 将 `CandidateExecution` 接到原有候选记录、账本、受限上传、一次性提交及
`FollowingService`。受信控制器可从一个已准备的普通科研任务，推进到已保存分析报告。
同一个候选使用确定的尝试键，刷新或重启不能改名重新计算。

此阶段是后台连接代码，尚未开放网页提交按钮或部署真实执行。用户不需要自行写
LAMMPS 输入；受信部署、科学检查及许可签发应由独立控制端落实。代码没有替这些环节
创建批准，也没有用准备完成、签名正确或摘要格式正确证明科学检查通过。

## 请求与许可的关联

1. 从当前冻结条件和持久候选记录读取输入，不接受浏览器指定任意文件路径或提交键。
   条件摘要、生成记录中保存的条件身份、生成上下文摘要、模型请求身份和输入快照必须
   一致。实际字节再次核验；论文模式和参考来源输入仍受原有发布/隔离门限制。
2. 使用已注册的评测，要求角色为 `agent` 且任务身份等于该普通研究的冻结条件摘要。
   评测由控制端预先注册，不在此服务中创建。该任务身份与 manifest 中的生成上下文摘要
   用途不同，后者由执行许可精确绑定；二者不能混用。
3. 按原始资源预留并渲染确定的资源脚本。当前启动器只支持单核，时间必须整分钟、内存
   必须整 MiB；不兼容时拒绝，不偷偷缩小请求。准备计划不会上传、派发或调用模型。
4. `ExistingAuthorization` 读取私人控制目录中已经签发的许可、密钥及已批准资源脚本，
   验证签名、到期时间、请求、输入、资源、输出、软件、运行配置、已审查提交和固定的
   批准/评分/静态检查身份。脚本字节必须与本次确定渲染的脚本相同。
5. 许可通过后进行一次受限上传；上传后再次核验有效期及全部绑定，再将许可内容、资源
   脚本和固定策略的摘要写入不可替换的账本事件，之后才由提交服务抢占派发。
   许可内容摘要与计算节点执行意图使用相同定义，不公开密钥或许可正文。
6. 已经派发的请求只进入原有跟进服务，过期许可不妨碍核对已存在的作业。未知提交按原
   请求核对；不再次上传、派发或生成新尝试。上传结果不明保留为待核对，不自动重传。

上传、提交、资源脚本与回收须配置同一登录入口、解释器和请求根目录；资源脚本启动器
必须与回收端固定的 runtime helper 一致。远端仍独立核验其安装的配置、许可和文件。
本地许可镜像不证明远端已经安装相同许可或完成身份隔离。

## 后台接口

受信部署组装 `CandidateExecution(tasks, ledger, snapshots, staging, submission, following,
authorization, environment)`，其中工具与路径来自管理员配置，不来自生成模型。

- `prepare(task_id, evaluation)` 返回已预留请求、确定输入及资源脚本，供控制端核验。
- `advance(task_id, evaluation)` 在具备许可时完成上传/一次派发并执行一次后台跟进。
- `run(task_id, evaluation, stop=..., notify=...)` 继续跟进至分析完成或待核对。
  停止不取消已有 HPC 作业；科学状态仍为未核验。

当前没有自动签发/安装许可、真实代码审查或科学检查服务。固定身份必须来自受信的
已核验部署，不能让 Agent 填入任意摘要冒充批准。密钥和镜像控制目录不得对主 Agent
开放。正式权限隔离、源代码隐藏与真实部署继续是未完成验收。

候选记录只支持第一版方案，尚未增加一次修复的候选版本管理。本服务不能通过创建新
评测绕过两次上限；后续修复必须保留同一评测和完整历史。文献测试的无答案任务发布、
作者参考端连接、真实模型/计算、OVITO 和独立评分仍需继续完成。

## 验证边界

测试实际调用合成响应下的候选生成、ASE 几何准备、势函数绑定、输入冻结、账本、文件
接收程序、远端提交辅助程序的许可/脚本检查、本地子进程字节回收以及数值分析。外部
模型响应、调度器和网络由合成数据替代；生成的 LAMMPS 文本从未执行。目标输出为手工
给定的合成数值，只证明软件连接和约束，不能证明 Agent 的物理方案正确或科学复现。

覆盖缺许可、错误批准身份/资源/输出/脚本、上传时过期、上传未知不重传、派发未知不重提、
任务身份与角色不符、输入变化、提交前取消、完成后许可过期仍可读取状态，以及不可替换的
授权摘要。重复执行完整合成链路保持一次模型替身调用、一次派发和一次下载。

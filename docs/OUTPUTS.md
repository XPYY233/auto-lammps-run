# 计算结果回收

Issue #33 补齐 `fetch_outputs` 领域操作。受信服务读取已结束、已完成核算的作业输出，
为后续分析提供保留原始字节和来源的本地结果包。普通研究与参考运行共用此接口；
参考结果的访问仍由部署身份控制，不向被测 Agent 发布。

`OutputCollector(ledger, endpoint, directory).fetch(request_id)` 使用账本确定请求、输入摘要、
作业号和存储限额。endpoint 复用 `StageEndpoint` 的配置结构，但 helper 必须指向管理员安装、
摘要固定的新版 `runtime_launcher.py`。其 `--collect` 入口只读文件，不执行模拟或调用调度器。
已结束但没有最终核算的请求、状态未知或有调度冲突的批次均不能回收。

## 数据与状态

启动器的执行意图新增批准输出名清单。远端只传这些平面输出和指定的执行/调度诊断，
不打包整个工作目录，不传输入脚本、势函数、控制目录或授权密钥。每个文件独立校验大小、
摘要、普通文件类型和链接数；逐级拒绝路径中的符号链接。传输前后重复检查文件稳定性，
使用有长度上限的清单和分块传输，不把完整轨迹读入内存或编码为 JSON。

- `collected` 只表示传输完整且通过身份/文件核验；科学状态始终为 `not_evaluated`。
- 引擎非零退出、执行回执缺失或声明输出缺失都如实保留；它们不能用于声称计算成功。
- 启动器尚未执行但已有匹配的调度接受回执时，可以回收调度诊断。既没有匹配执行意图，
  也没有匹配接受回执的情况拒绝回收，需要先核对来源。
- 旧版执行意图没有输出清单，不能据此猜测哪些文件可传。

本地再次读取已经完整回收的请求会重新校验文件并复用结果；文件损坏时直接报错。
断流、超时和进程退出不触发重新提交计算。明确再次调用回收可以新建下载记录，旧的失败
目录及已占用额度保留；锁由操作系统管理，进程退出后释放，不能仅因超时就认定另一个下载已停止。

## 预算与历史

每次下载前，账本以事务预留“原作业存储限额 + 256 KiB 本地回收元数据空间”。这些费用
叠加到同一批次的原有存储预算，并发请求不能重复消费最后一份额度。失败或中断下载也不
自动退还存储；现阶段没有自动删除和释放额度的保留策略。若原作业已经预留全部批准存储，
回收会因没有副本空间而被阻断；应在执行前统筹运行树、远端文件与本地副本。

账本追加 `output_fetch_started` / `output_fetch_finished` 历史，关联下载票据和私人回执摘要；
不改变提交次数、作业终态或核时。回执写入失败不会标为已回收，调度证据在传输中改变也
不能发布成功记录。这是逻辑字节记账，文件系统物理配额与所有运行缓存的统一计量仍需部署验收。

管理员可运行一次现有请求的回收：

```sh
python3 -m auto_lammps.outputs \
  --ledger /private/service/ledger.sqlite \
  --ssh-alias approved-host \
  --python-path /approved/python3 \
  --runtime-helper /approved/runtime_launcher.py \
  --helper-sha256 REVIEWED_HELPER_SHA256 \
  --requests-root /private/service/requests \
  --directory /private/service/downloads \
  --request-id EXISTING_ACCOUNTED_REQUEST_ID
```

以上为占位配置，不构成执行授权。关闭网页不影响该接口，但尚未接入持续后台计算 worker、
网页结果页、物理量解析、OVITO 或科学评分。合成文件的真实本地子进程传输、进程退出恢复
及并发预算检查已覆盖核心路径；没有真实 HPC 文件回收或完整科学任务验收。

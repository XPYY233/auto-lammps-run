# 网页方案准备与历史

Issue #25 将候选生成器接入研究任务页面。冻结条件后，已配置的服务显示“准备计算方案”。
请求只携带任务版本，后台继续处理；关闭页面不会取消准备。页面每 3 秒读取进行中的阶段，
显示真实更新时间、方案摘要、结构组成、待补充问题及下载入口。不提交 HPC，不将准备计为计算提交。

## 持久记录与恢复

沿用私人任务数据库，新增不可更新/删除的 `candidate_jobs` 和 `candidate_events`。
后台启动前写入意图，保留排队、条件检查、模型请求、文件准备及终态。
一个冻结任务当前只允许一个首次准备意图；重复点击、刷新或并发请求返回同一记录。
网页不能重置历史或修改额度；模型请求仍由 `ModelCalls` 记账。

后台持有该意图对应的操作系统文件锁。另一个服务或查询只有取得锁并再次确认状态，
才能记录中断，不根据等待时长推定进程死亡。真实进程退出测试覆盖模型意图已记账、
回执与终态尚未写入的情形；重启后保持已消耗意图，不自动重发。
尚未开始的排队项仅在代码、模型配置、资源和保存位置一致时继续；配置改变留档阻断。

失败和待补充状态也保留。当前尚无“答复后修订冻结条件并继续”的入口，后续需保持同一任务、
历史与计算次数约束，不能新建任务掩盖失败。未知模型请求仍需核对，不能自动重新生成。

完成后保存候选与快照摘要。下载时重新验证全部快照文件，只提供计算输入、结构、分析说明和
准备记录；浏览器不能指定本地路径。模型服务关闭后仍能阅读历史，下载需恢复原服务配置。

## 配置

默认不开启候选生成。管理员提供已有模型账本和私人资源 JSON：

```sh
python3 -m auto_lammps.web --data-directory "$HOME/.local/share/auto-lammps-private/workbench" --port 8785 --model-ledger MODEL_LEDGER --candidate-config CANDIDATE_CONFIG
```

JSON 字段为 `potential_catalog, allowed_pins, software_sha256, packages, resources, max_atoms`；
可选 `legacy_snap_pins` 仅供管理员指定经过审查的旧 SNAP 参数转换，详见 [资源适配](POTENTIALS.md)。
资源字段使用现有 `cores, wall_seconds, memory_bytes, storage_bytes`。
此配置不创建或提高模型预算，凭据不写入 JSON 或网页；它也不构成计算执行授权。
后台工作池使用 [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/) 管理。

## 验证边界

测试覆盖并发服务、排队恢复、配置变化、真实 worker 退出、活动锁、不可删除的失败记录、
API 来源边界和下载篡改拒绝。独立合成服务的浏览器验收覆盖准备入口、生成状态、摘要、
96 原子结构记录、下载入口、历史展开和服务重启。重启前后合成模型请求保持一次。
这些不是物理结果或真实模型能力证据。

仍需科学条件核验、可追溯条件修订、输入发布/隔离、一次修复、真实 HPC、回收分析与 P-A-B 验收。

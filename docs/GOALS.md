# 项目目标

交付科研人员通过浏览器使用、课题组能自行维护部署的自然语言科研计算服务。用户不需要提供论文或编写脚本；主 Agent 设计方案，经领域 Adapter 完成结构、势函数、LAMMPS、HPC、分析与报告。必要澄清保留，不能用隐含默认值改变任务。首先审计已有自动计算和文献提取代码，按明确接口复用，不重建通用 Agent 框架。

文献复现属于可靠性测试：基于已有文献工作台自动生成无答案自然语言任务，以作者参考运行建立 P-A 依据，把测试任务交给同一产品入口和执行链路得到 B。源码测试集库负责参考依据，势函数库服务实际计算；两者关联但权限分开。第一周的一篇论文是首个验收门槛，不是产品最终范围。没有已知参考答案的新研究任务也应能运行，但不能伪造 P/A 或宣称通过论文比较。

第一周的自动化主体是软件自身：用户提供论文和自然语言需求，集中确认范围与科学条件，处理确实缺失或冲突的信息；其余流程由应用推进。开发者手工整理和运行不能代替这项验收。见 [第一周自动化验收](WEEK1_ACCEPTANCE.md)。

| 阶段 | 交付和验收 |
|---|---|
| 第一周 | 一篇真实论文的明确任务集合；P-A 核验、无答案任务包、独立生成 B、HPC 执行、分析和 P-A-B 比较；网页输入、确认、进度、结果与导出 |
| 第二周 | 从真实失败改善条件检查、势函数、生成与解析；现有流程基线、重复评测、一次失败到改进 PR 再复验 |
| 第三周 | 扩大独立来源、任务族及资源索引；冻结版本、分组、容差、预算后评测，报告置信区间、覆盖和失败 |

第一周实测成本之后才提议并确认后续样本量，不预定虚假的论文数量或保证 90%。三周是验收顺序，不代表会话会无人值守持续运行。每次中断保存状态和恢复入口。

工作包：PR 0 审计与候选；PR 1 受控 HPC、持久记账与防重复；PR 2 任务条件及势函数；PR 3 文献适配、任务包及参考运行；PR 4 模型连接与一次修复；PR 5 分析与真实网页闭环。依赖和实测优先于编号。第一周不做微服务、Kubernetes、复杂账号体系或模型训练。

输出优先级：真实可核验复现 → 条件及权限 → 可追溯 → 稳定 → 覆盖 → 界面。

已认可技术路线还包含任务与结果分享、自定义工具接入及开源文档；作为后续扩展保留，遵守资料许可和发布授权。产品主流程、源码测试集库与势函数库先完成，不以社区功能代替前三周验收。

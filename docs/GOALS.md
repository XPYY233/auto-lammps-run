# 项目目标

交付科研人员通过浏览器使用、课题组能自行维护部署的自然语言科研计算服务。用户不需要提供论文或编写脚本；主 Agent 设计方案，经领域 Adapter 完成结构、势函数、LAMMPS、HPC、分析与报告。必要澄清保留，不能用隐含默认值改变任务。首先审计已有自动计算和文献提取代码，按明确接口复用，不重建通用 Agent 框架。

文献复现属于可靠性测试：基于已有文献工作台自动生成无答案自然语言任务，以作者参考运行建立 P-A 依据，把测试任务交给同一产品入口和执行链路得到 B。源码测试集库负责参考依据，势函数库服务实际计算；两者关联但权限分开。第一周的一篇论文是首个验收门槛，不是产品最终范围。没有已知参考答案的新研究任务也应能运行，但不能伪造 P/A 或宣称通过论文比较。

按用户最新澄清，第一周由 Codex 负责跑通真实 P-A-B 流程，第二周开始接入独立 API 并验证自动化。A 直接运行作者源码及原有入口/配置；B 独立编写输入，开始前须先报告策略并获用户确认。首次 P-A-B 跑通后重做面向研究者的界面，不能依靠开发者后台补步骤通过使用验收。见 [第一周流程验证](WEEK1_ACCEPTANCE.md)。

| 阶段 | 交付和验收 |
|---|---|
| 第一周 | 一篇真实论文的明确任务集合；P-A 核验、无答案任务包、独立生成 B、HPC 执行、分析和 P-A-B 比较；网页输入、确认、进度、结果与导出 |
| 第二周 | 接入用户提供的独立运行 API，验证产品自动化；从真实失败改善条件检查、势函数、生成与解析；现有流程基线、重复评测、一次失败到改进 PR 再复验 |
| 第三周 | 扩大独立来源、任务族及资源索引；冻结版本、分组、容差、预算后评测，报告置信区间、覆盖和失败 |

第一周实测成本之后才提议并确认后续样本量，不预定虚假的论文数量或保证 90%。三周是验收顺序，不代表会话会无人值守持续运行。每次中断保存状态和恢复入口。

工作包：PR 0 审计与候选；PR 1 受控 HPC、持久记账与防重复；PR 2 任务条件及势函数；PR 3 文献适配、任务包及参考运行；PR 4 模型连接与一次修复；PR 5 分析与真实网页闭环。依赖和实测优先于编号。第一周不做微服务、Kubernetes、复杂账号体系或模型训练。

输出优先级：真实可核验复现 → 条件及权限 → 可追溯 → 稳定 → 覆盖 → 界面。

已认可技术路线还包含任务与结果分享、自定义工具接入及开源文档；作为后续扩展保留，遵守资料许可和发布授权。产品主流程、源码测试集库与势函数库先完成，不以社区功能代替前三周验收。

文献清单、复现记录及涉及具体论文的阶段汇报必须给出完整发表题目和核实的 DOI/链接。候选与已选任务分开，已选任务区分待复现、复现中、已复现；保留失败和排除原因。

## 当前第二周验收（2026-10-06）

完成一次真实用户端自然语言到 HPC、分析、图表和结果讨论的完整流程，并准备/执行三篇
论文的同流程 PAB 验证。文献工作台提取正文得到 P（论文结果与出处），另提取允许的
研究条件；运行固定作者源码得到 A；把仅含条件、结构/势函数资源的无答案自然语言
提示词输入普通科研用户端得到 B。不另建文献专用 B 执行链，不把私有控制脚本的成功
当作产品验收。先列全篇目标、选定可支持的工况、固定比较标准，再进入 A/B；历史
事后审计不能补作事前冻结。准备三篇和三篇科学复现通过分别报告。

最新用户裁定：当前 W 空位任务仅用于核验流程完整性，不纳入准确度样本、成功率或
PAB 科学评分。其实际失败、提交次数、费用、输出和收敛诊断仍保留。

后续 B 从正常用户端的输入、方案查看/修改/批准、提交、状态跟进到结果查看，均经
应用页面入口完成。应用后台服务执行按钮触发的操作属于产品流程；开发者不得用私有
脚本、直接改数据库或人工串接阶段补成一次成功。遇到报错先留存失败并检修应用，
再从页面恢复同一任务；不改写冻结条件、评测身份、旧结果或提交次数来绕过失败。

## 三篇 PAB 的执行与验收要求（2026-10-07 重申）

三篇用于检验同一自然语言科研产品流程，不能另建私有论文演示链。逐篇执行：

1. **先核实成套资源。** 优先复用本地 Zotero 正文、文献工作台及 harness 已核验成果；
   给出完整题目/DOI，固定作者源码版本、结构/初始化数据、全部势函数和参数、依赖、
   来源与许可。源码及模拟工作文件留在配置 HPC；资源齐全不等于科学通过。
2. **先选目标，再执行。** 识别全文图、子图、表格及补充材料，关联工况、输出、采样、
   分析方法与缺项；集中选定有科学意义的完整任务范围，说明排除项。查看 B 前固定
   比较指标、单位、归一化、拟合/采样区间、数字化不确定度和容差；不能挑容易数值
   或事后补作事前冻结。多工况按明确任务边界拆分，不用图数伪增独立样本。
3. **P：论文原始结果。** 复用文献工作台取得正文中的结果数值、曲线/表格及出处；
   保留数字化和人工修正记录。条件整理是另一份产物，不能用条件提示词替代 P。
4. **A：作者源码参考运行。** 直接执行固定作者源码及其原有配置/流程，不独立编写
   A 输入。必要环境/路径适配逐项留痕；先核验 P–A，偏差或缺输出须保留，不能自动
   将正常退出认作合格参考。
5. **B：正常用户端独立运行。** 只将允许条件、结构/势函数资源及通用知识整理为无答案
   自然语言需求；经普通应用页面、配置的项目 API 和主动 Adapter 完成条件确认、
   方案迭代/批准、提交、跟进、回收、分析、可视化和结果讨论。进入 B 前报告策略并
   获确认；隔离 P/A、作者解法和评分答案。开发者不代写方案、不用后台脚本补步骤；
   报错先记录并检修产品，再由页面恢复同一任务。
6. **次数、资源和历史。** B 每项正式评测最多两次真实提交，状态未知先对账，不能
   重建身份或隐藏试跑绕过次数。每任务累计上限 9216 CPU 核时、禁止 GPU；单作业
   32 核/8 GiB、并发 1、集群七天硬限制继续。全部目标物理求值经记账 HPC 入口，
   保存失败、人工介入、模型用量、核时、费用与各版产物。
7. **结果与通过证据。** 按事前固定标准逐项比较 P–A、A–B、P–B；分别报告调度完成、
   输出有效与科学通过。网页提供原文对照、实际图表、带单位数值、P/A/B 全称、
   原始/派生文件下载、分析依据和历史。正式比较与追加诊断分开，不改阈值求通过。

W 空位案例只验证流程，排除准确度与三篇 PAB 科学评分。旧拉伸基准保留已接受的单工况
身份，不重写为未复现，也不能冒充第二周 API 用户端 B。当前三篇是否包含旧基准尚未
明确，第三篇新增资源尚未匹配；保留该范围缺项，不自行减为两篇或宣布三篇已就绪。

## 方案轮次与通过率（2026-10-07 最新裁定）

每个任务首版在内最多三轮方案生成；自动修订、非法 JSON 修复、人工要求修改和运行
失败后的改版共用该任务的持久计数。完整方案须在三轮内形成；否则保留失败并停止，
不能追加第四轮、改名重建或强行批准。刷新、服务重启、配置重新基线不恢复轮次。
只读核对与审批不重写方案，不计方案生成轮次；模型用量仍全部记账。已有完整合格
方案达到三轮后仍可查看和批准，不能以达到上限为由阻止实际提交。

正式 B 的 HPC 提交仍最多两次，独立计数。阶段目标是在方案三轮和 HPC 两次边界内，
科学/流程通过率至少 90%；准备失败、提交失败和未完成不能从已选评测分母删除。
三个预选案例至少须 3/3 通过才能达到本次样本目标；仍报告样本量、失败和不确定性，
不把三个案例推论为总体 90% 可靠性。现阶段未完成这项实测。

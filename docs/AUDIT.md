## 2026-09-25：用户补充的三项根本执行偏差

1. **重工程、轻自动化主线。** 基础模块、审计和代码检查的投入超过实际科研任务推进，
   没有把“需求到真实结果自动衔接”作为核心验收。之后每项工程工作须说明解决哪个当前
   用户步骤或具体阻塞；不能用更多接口、PR 或测试数量替代真实计算链路。
2. **重功能可用、轻用户需求。** 程序可调用、表单可保存，却要求研究者理解内部字段和
   手工串联步骤。以两张批准的最终预期图及从空白页面完成用户任务验收，结果、进度、
   提交次数与历史清楚可见；技术细节按需展开，用户只处理真实科学缺项或决策。
3. **重自建、轻已有资产和自主获取。** 未持续优先复用文献工作台、Zotero 正文、可公开
   下载的补充材料和源码、已有势函数及超算环境。顺序改为核对已有有效证据并复用 →
   自行获取授权范围内可得资源 → 处理具体剩余缺口。数据解析、分析及可视化同样先查
   现有代码与 OVITO 等成熟工具，不能默认重写或让用户提供已经能够取得的资料。

已将规范入口、这些教训、两图实际复看要求和阶段边界整理为本地
`auto-lammps-stage-guide` 技能。该技能供开发端承接，不进入被测 Agent 的答案检索空间。
它不是新的审批层，也不证明运行端已实现自动化；整理后立即返回原作者 A 主线。

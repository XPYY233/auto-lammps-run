# 项目审计

## 2026-09-25：三次真实 A 提交的执行错误

以下是当前状态；后续各节保留当时的审计截面。三次都到达调度器，但尚未产生 LAMMPS
计算结果，不能称 A 已跑通。用户批准的第一周三次额度已用完；没有自动重置或额外提交。

| 次数 | 现场证据 | 开发错误及修正状态 |
|---|---|---|
| 第一次 | 启动器拒绝带参数的 Slurm SubmitLine，8 核、6 秒，48 核秒 | 把空格当字段分隔符，离线样本没覆盖真实命令字段。Issue #73 已修复；下一次作业通过分配解析，确认此项修复有效 |
| 第二次 | 8 核/8 GiB 核验通过，默认 FUSE 辅助程序与登录端部署声明不一致；调度核算为 0 核秒 | 将登录端的辅助工具环境假设用于计算节点，并把输出封装放在作者计算之前。随后改用原生 Slurm 工作目录；固定输出卷的计算节点适配仍未修复，不宣称验收通过 |
| 第三次 | 32 核、61 秒，1952 核秒；MPI bootstrap proxy 启动失败，未产生 LAMMPS 日志 | 将此前隔离环境使用的强制 fork 设置带入原生 Slurm。日志提示 fork 无法启动被识别为远端的主机；已准备调度器原生 bootstrap 修正版，仅语法检查通过，具体原因与修复仍需运行验证 |

合计调度核算 2000 核秒，约 0.556 核时；零个合格 A。失败类别、原脚本、输出及费用全部
留在私有记录；基础设施故障不能从提交次数或端到端成功率分母中删除。

新增执行规则：Slurm 作业应优先沿集群原生 MPI 调度方式；隔离帮助查询的启动参数不能
直接搬到生产批处理。登录端检查只证明对应环境，不能作为计算节点能力证明。确定性
解析器须覆盖真实格式的脱敏样本；错误原因假设、代码修复、真实复验分别记录。
修正参考依据：[Slurm MPI 指南](https://slurm.schedmd.com/mpi_guide.html)、
[作业环境传递](https://slurm.schedmd.com/sbatch.html)。它们支持方案选择，不证明本次运行成功。

## 2026-09-25：用户补充的三项根本执行偏差

1. **重工程、轻自动化主线。** 基础模块、审计和代码检查的投入超过实际科研任务推进，
   没有把“需求到真实结果自动衔接”作为核心验收。之后每项工程工作须说明解决哪个当前
   用户步骤或具体阻塞；不能用更多接口、PR 或测试数量替代真实计算链路。
2. **重功能可用、轻用户需求。** 程序可调用、表单可保存，却要求研究者理解内部字段和
   手工串联步骤。以两张批准的最终预期图及从空白页面完成用户任务验收，结果、进度、
   提交次数与历史清楚可见；技术细节按需展开，用户只处理真实科学缺项或决策。
3. **重自建、轻已有资产和自主获取。** 未持续优先复用文献工作台、Zotero 正文、可公开
   下载的补充材料和源码、已有势函数及超算环境。顺序改为核对已有有效证据并复用 →
   自行获取授权范围内可得资源 → 处理具体剩余缺口。数据解析、分析及可视化同样先查
   现有代码与 OVITO 等成熟工具，不能默认重写或让用户提供已经能够取得的资料。

已将规范入口、这些教训、两图实际复看要求和阶段边界整理为本地
`auto-lammps-stage-guide` 技能。该技能供开发端承接，不进入被测 Agent 的答案检索空间。
它不是新的审批层，也不证明运行端已实现自动化；整理后立即返回原作者 A 主线。

## 2026-09-25：已有引擎未优先复用，A 被不必要的编译路线拖延

本次错误由开发执行造成。用户已提供论文并要求运行作者代码；固定作者源码、结构和
MEAM 文件已取得，集群也有已编译且帮助输出明确包含 MEAM、`meam` 和 MPI 的版本。
开发过程中仍把新编译路线当成 A 的必要前置，并反复请求该路线的代码审查确认。
本节记录事实与纠正，不把文档更新算成参考计算完成。

| 错误 | 实际影响 | 纠正 |
|---|---|---|
| 没有把已有环境审计用于下一步决策 | 已找到 28 Mar 2023 的 MEAM/MPI 程序，仍围绕新源码继续搭建编译入口 | 先复用已证实可用、且用户明确接受的安装；只有具体缺失功能才构成安装或编译理由 |
| 将部分模块缺少 MEAM 扩大为必须重新编译 | 被查询的 2 Aug 2023 模块确实缺 MEAM，但不代表整个集群缺少可用 LAMMPS | 分别记录模块、实际版本和功能；不能从一个模块外推整个集群 |
| 对版本差异采用了不必要的执行前置 | 作者说明为 Windows 2 Aug 2023，已有 Linux 28 Mar 2023；版本不同被直接处理成重建要求 | 记录真实环境差异及适用证据；用户现已明确接受已有兼容版本，不再重复征询同一决定 |
| 混淆代码、准备资料和真实就绪 | 多次报告源码、账本、部署检查进展，实际 A 提交仍为零 | 分开报告“文件齐全”“程序存在”“作业已提交”“计算完成”“科学核验通过” |
| 把可选编译路线的 PR 审查变成 A 的统一门槛 | PR #70 等待审查，继而将目标标为受阻，拖延已有引擎路线 | PR #70 只涉及该编译实现；不能据此阻塞不使用它的 A。保留其历史，不冒称已获独立审查 |
| 对已核实事项反复检查，缺少执行推进 | 重复帮助、路径、版本和准备状态检查，没有取得真实参考输出 | 已有证据持续有效时复用；仅因输入变化、真实错误或未解决的具体问题重查 |
| 对 P 的进度说明不够精确 | 两张表的数值核对容易被理解成全文 P 已审计完成 | 158 个表格数值已复核；曲线、补充图及评分口径未全部完成，分别标记 |

已发生的查询失败也保留：首次帮助查询受登录端 MPI 通信初始化影响，不能据此判定
LAMMPS 缺失或不兼容；限定共享内存通信后帮助查询成功。首次编译部署检查因系统
格式化工具的普通硬链接被拒，之后修正并通过。两项均不是论文模拟结果。

纠正后的当前路线是：使用用户明确接受的已安装程序，按作者原脚本、原结构、原势函数
和完整步骤提交 A；记录操作系统、LAMMPS/MPI 版本、资源、输入摘要及真实返回结果。
A 不是重新生成独立输入；仅有必要路径适配时逐项留痕。B 的独立生成及进入前策略确认
保持不变。原始 A 的执行与正式科学评分分开；不得在看到结果后选择有利的目标或口径。

截至本次记录：未派发的编译准备请求已取消，预留的 4 核时已释放，没有取消运行中的
作业，也没有发生编译计算费用；原文件、失败记录及保守存储预留保留。A 尚未提交，
B 尚未启动，未调用真实模型 API。最新指令已解除不必要编译路线造成的阻塞；这不等于
宣布第一周目标完成，下一步必须以真实 A 的作业回执和输出推进。

本节公有版本不含集群路径、账号、作者源码副本、隐藏目标值或私有日志；完整证据索引
保存在私有项目审计中。关联 Issue #71。

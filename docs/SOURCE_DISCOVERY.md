# 论文源码检索

参考端 `SourceDiscovery` 从论文题目与 DOI 查询 GitHub 代码索引，核查候选仓库的 README，
将题目与 DOI 同时匹配的仓库标为关联证据。它不自动证明作者身份、代码许可或科学复现成功。
不克隆、不安装、不运行仓库代码，不调用模型或提交 HPC。

管理员使用既有 GitHub CLI 登录；查询显式固定 github.com 和 GET。每轮最多 3 个查询、
10 条索引结果/查询、5 个不同仓库、18 次请求；每次限制 30 秒、2 MB。
搜索采用完整 DOI、标识尾段和规范化题目。短尾段可能产生大量无关命中，必须核查 README；
索引截断、不完整响应、失败或候选上限均保留，不能把它们解释为不存在作者源码。
即使本轮全部请求成功，也不声称搜索穷尽全部来源。

仓库须为公开仓库；先固定默认分支提交，再按提交读取 README，校验 Git blob、长度和 SHA256。
报告只保存链接、版本、匹配标志与 GitHub 许可元数据。没有许可或许可元数据存在均不自动授予
再分发权。README 作为不可信资料读取，不解释其中的指令。软件不读取仓库安装脚本。

调用前将意图写入 Git 外私人目录；每次请求与响应分别独占保存。超时与错误保留，
不自动重试。进程中断留下未完成意图，不伪造完成结果；需要新一轮检索时使用新标识。
完成报告可重复关联原论文，重复关联不添加历史；不同轮结果保存在不可覆盖的文献修订中。

管理员入口（路径由部署端填写）：

```sh
python3 -m auto_lammps.source_discovery \
  --database /private/workbench/tasks.sqlite \
  --paper-id PAPER_ID \
  --audit-directory /private/reference/source-searches
```

这仍是参考端控制入口，尚未接成从上传论文自动触发的后台流程；最终用户无需执行上述命令。
网页“复现文献与历史”已经可以展开“论文源码检索”，查看最近报告、关联状态、版本与许可。
完整请求、README 和错误响应留在私人证据目录，不经网页导出。没有新增主 Agent 检索工具。
这些管理接口与数据库必须按现有部署要求隔离，不能把网页只读展示视为 B 的访问隔离验收。

本轮真实检索独立找到选定论文的关联仓库，README 题目与 DOI 相符，固定版本与既有私人
源码清单一致。尾段搜索出现无关命中并达到上限，报告如实为 partial；只有一个候选匹配
题目和 DOI。其他命中仍为未确认，不纳入已验证测试集。网页已核对新报告与待复现状态。

接口依据：[GitHub REST 仓库内容](https://docs.github.com/en/rest/repos/contents)、
[GitHub CLI API](https://cli.github.com/manual/gh_api)。全部 CI 测试使用合成响应。

题目与 DOI 均匹配的仓库只有一项时，控制入口现在自动调用 [MEAM 资源准备](POTENTIAL_ACQUISITION.md)，
将势函数文件和调用要求记入网页与文献历史。多个匹配仓库不自动选一个，缺少匹配不猜测来源。
这仍不等于论文上传后已经全自动启动检索，也未启用真实模拟。

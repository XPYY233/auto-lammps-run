# 受限上传与资源脚本

本阶段实现可调用的文件传输客户端、独立接收程序与 Slurm 脚本生成器。没有实现或启用实际 sbatch 提交，也没有将接收程序部署到真实集群；不能称为完整的生产执行适配器。

## 输入传输

受信控制端先通过 Ledger.reserve 预留资源，再调用 StagingService.stage。输入摘要和资源必须与账本完全一致。上传意图在 SSH 前写入账本；重复调用不再次发送，未确认上传保留存储占用与私人回执。上传失败不增加实际计算提交计数。

StageClient 复用批准的 OpenSSH 别名，严格验证主机密钥，禁用交互、转发和本地连接钩子。只调用配置中固定的 Python 解释器及接收程序；接收程序必须位于可写输入根目录之外，源文件摘要必须匹配批准版本，不能由输入包替换。-I 隔离 Python 用户环境。实际解释器、SSH 配置及服务安装目录仍属于管理员信任边界。

传输协议只包括有界 manifest 和按其顺序排列的原始文件字节，不解包归档、不执行上传文件。客户端再次校验冻结字节；接收端独立验证清单和每个文件摘要。仅允许普通文件，路径最多八层，禁止越界、链接、重叠路径、控制文件名与额外尾随数据。

接收目录采用请求编号，只创建一次。断线、摘要错误或超时留下部分文件及原始占用记录；不覆盖、不清理、不自动重传。完整接收才写 stage.json。后续需要增加私人状态查询与受控清理/恢复操作，不能把已有目录当作可安全重提的证明。

## 服务端存储策略

管理员预先建立仓库之外、服务身份拥有且权限为 0700 的根目录，安装 policy.json（0600）：

```json
{"schema_version":1,"max_total_bytes":1048576,"approval_sha256":"APPROVED_RECORD_SHA256"}
```

这是说明性结构，不是有效批准记录或真实配置。部署时必须使用实际批准摘要和上限；程序不会自动创建策略或取得授权。每个请求的 storage_bytes 来自已冻结资源。

服务端使用文件锁串行占用，累计既有请求预留；部分上传同样计入。额外预留 64 KiB 根目录控制文件额度，每请求至少给回执留下 8 KiB。没有有效占用记录的旧目录阻止后续上传。服务端接收进程和客户端都设有最长 60 秒期限；超时需检查，不盲目续传。

该限制针对协议声明的**逻辑字节与预留值**，不等于文件系统物理占用硬配额。目录元数据、文件分配块、本机快照/回执副本以及计算输出的总量控制尚未完成。正式运行需要核实并落实这些总存储限制，不能把预留检查当作完整存储隔离。

## 资源脚本

batch_plan.render_batch 固定请求标识、manifest comment、单节点、请求核数、整分钟墙钟申请、整 MiB 内存、输出目录、禁止重排队和受信启动器摘要。不接受分区/账户中的指令注入，拒绝会被 Slurm 向上取整的非整分钟时限，以及非整 MiB 内存。不调用引擎、sbatch 或任何模拟预检查。

使用 --export=NIL 避免 Slurm 隐式恢复用户登录环境；区别与 --mem 含义依据 [Slurm sbatch 文档](https://slurm.schedmd.com/sbatch.html)。仍须在目标版本验证支持。声明资源不证明实际分配核数、内存 cgroup 或网络/文件权限已经被强制限制。

脚本引用管理员安装、摘要固定的运行启动器。**该启动器尚未实现或部署**；它必须核实批准记录、计算节点身份、实际资源、输入、允许的命令、权限与输出配额，再运行一次目标流程。不能用任意路径或“已隔离”布尔标记代替这些验证。此阶段提供可审查脚本，不提供可直接提交目标计算的命令。

## 已验证与剩余工作

95 项离线测试通过，包括真实子进程的文件流传输与摘要固定程序校验、两个进程争抢最后存储额度、账本前置记录、重复请求、断流、截断、摘要损坏、额外字节、恶意路径、链接、错误回执及资源指令。输入均为合成文本/字节；没有本机或 CI 物理计算。

并发测试曾复现锁文件创建失败；改成排他创建后打开已有锁，并完整回收测试子进程，保留修复经过。公开测试和记录不包含集群配置或真实科研数据。

真实登录入口只读发现了隔离相关程序，但程序存在不等于计算节点上可用或隔离有效。未执行命名空间、容器或目标引擎探测；原始查询存于私人审计。

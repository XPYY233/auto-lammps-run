# 计算提交后的自动跟进

Issue #39 将已有的调度核对、输出回收、冻结计划分析与网页历史连接为
`FollowingService`。受信后台指定一个已有派发请求后，服务等待作业结束和资源核算，
自动回收输出并运行同一 `AnalysisService`，报告进入原任务结果页。
普通科研与文献验证使用相同服务；参考角色的结果仍不进入产品主 Agent 的结果视图。

本阶段连接的是**提交后的流程**。还没有将网页候选、真实许可签发、HPC 提交和后台启动
整体部署，也没有真实科学任务完成。它不创建评测或执行许可，不提交/取消计算，不调用
模型，不在本机做目标物理计算。

## 持久状态与中断

- 跟进策略第一次使用时绑定到账本请求：输入目录、回收/分析目录、查询入口与记录目录、
  辅助程序身份、分析实现及本服务版本。查询与回收必须使用同一已配置登录别名。
  更换策略或放大查询额度会被拒绝，重启不会重置累计记录。
- 每次查询前预留一次查询机会与存储空间，之后调用原有持久对账服务。最多 240 次查询，
  间隔至少 15 秒；调度未知或暂时不可读可以在该上限内继续查询，不重提计算。调度冲突
  立即停止自动处理。计数/存储不足显示待核对，保留已有作业和记录。
- 每次查询包括至多两个原始调度响应及其回执。按 `3 × (query_max_bytes + 1) + 16384`
  字节保守预留记录空间，失败查询同样保留费用；实际物理存储配额仍待部署验收。
  手工旧式一次对账入口没有自动获得本策略，不能以此声称全部历史查询已纳入预算。
- 同一账本使用操作系统锁串行跟进。另一进程返回正在处理；锁随进程退出释放，不能根据
  锁文件存在判断进程仍在运行。查询时间间隔同时保存在账本中，快速重启不能加速查询。
- 终态且完成核算后自动回收一次。失败或中断下载的副本与费用保留，不自动开启新的下载；
  已存在完整回收记录时复核并复用。中断在报告保存之后，重启可通过现有确定身份恢复，
  不增加计算、下载或报告次数。
- 作业失败时只保存诊断，不分析出性质。正常结束但分析检查失败，保存分析失败；所有
  状态仍是科学未核验。跟进过程写入同一账本，任务历史显示开始、回收、分析及待核对。

`attention` 停止本轮自动处理；目前没有重置上限、覆盖历史或批准再次下载的网页入口。
损坏的半写报告仍需后续受信恢复功能。终态跟进结果是历史完成记录，重复启动不重新验证
全部文件；网页展示报告时继续核验报告及回执，完整原数据复核见回收与分析服务。

## 受信后台接入

`FollowingService(ledger, reconciliation, analysis, snapshots, max_polls=..., interval_seconds=...)`
提供 `advance(request_id)` 单步接口与 `run(request_id, stop=..., notify=...)` 持续接口。
上游控制器应在已授权的提交之后启动它；不能把生成模型输出当成部署配置。
停止后台跟进不会取消已经在 HPC 运行的作业。

管理员现有 `python3 -m auto_lammps.worker` 增加 `--follow-config`；同时必须提供一个
明确的 `--request-id`，并保留已有 `--ledger`、`--ssh-alias`、`--audit-directory`。
不带配置时继续保持原有的一次对账行为。配置是 Git 外的私人 JSON，严格包含：

| 字段 | 含义 |
| --- | --- |
| snapshots_directory | 已冻结输入的目录，子目录名为快照摘要 |
| collections_directory / reports_directory | 已配置的回收与报告目录 |
| endpoint | 现有 StageEndpoint：批准入口、解释器、固定 runtime helper、摘要及请求根目录 |
| max_polls | 同请求累计查询上限，1–240 |
| interval_seconds | 查询间隔，15–3600 秒 |
| query_max_bytes | 每个调度查询的输出上限，沿用 SlurmReader 的限制 |

CLI 输出不含原始调度响应的状态记录，收到停止信号后在当前有界步骤结束时退出。
退出码 0 仅表示数值分析完成；失败、待核对或停止为 2，不能当作科学成功评分。
监督进程重启、正式权限隔离及部署验收仍未提供，此次没有在真实 HPC 上启用跟进。

## 验证

合成调度状态与真实本地字节传输验证了运行中→核算→回收→分析→任务结果的自动推进。
包含查询间隔和额度的持久性、存储不足时不访问远端、并发工作进程、真实进程退出后恢复、
下载中断保留费用、失败作业只取诊断、失败分析保留、配置改变拒绝、已准备请求不能派发、
停止监督不取消作业，以及同一任务网页投影中的阶段记录和一次提交计数。
首轮新增测试有两处多行上下文语句语法错误，修正后才执行并通过；没有真实模型或目标计算。

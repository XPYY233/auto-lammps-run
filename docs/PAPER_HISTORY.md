# 文献清单与历史

本机工作台的“复现文献与历史”区分候选与选定文章，选定后按待复现、复现中、已复现显示。登记候选不意味着批准计算；加入计划不冻结科学范围或评分标准。

登记资料通过受信 Python `PaperStore.add(title, doi, scope, note)` 写入私人任务库。浏览器可以选入计划并关联已有复现任务。DOI 归一化后唯一，关联和历史不可覆盖。该目录不是 Zotero 全库镜像，也不是势函数目录。

条件修订和文献事件保留时间与版本。受信控制器通过 `bind_evaluation` 关联既有账本，必须传入已冻结任务对应的正式任务摘要；网页没有创建评测、重置次数、提交或写入成功状态的接口。条件导出的摘要与正式评测任务摘要用途不同，未来控制器需要完成并验证二者绑定；目前没有自动派发流程。

服务器可用 `--ledger` 读取既有私人账本。页面分别显示额度占用、记账派发、剩余额度、作业号、状态和最终核时；派发意图不等于已证明调度器收到请求。缺失账本显示次数未知，不能显示额度已恢复。原始事件的私有载荷不通过此接口返回。

冻结条件与调度器 completed 均不能产生“已复现”。独立评分发布尚未实现，因此当前已复现分类为空。已派发但未核验的文章归入复现中；额度用尽时另外明确标注停止重试。后续需要独立评分、失败/暂停原因及完整结果文件关联，不能将本模块称为完整科研轨迹管理。

页面每 15 秒读取一次，编辑或展开操作获得焦点时暂停刷新，保留已展开历史。此刷新仅查询本机记录，不访问模型或提交计算。

验证包含合成账本的两次拒绝与第三次阻断、重启后记录保留、不可覆盖历史、缺失账本、完成作业不发布科学成功、跨站请求及越权写入拒绝。真实候选在本机浏览器核验了清单、分类和历史展开；尚无真实提交历史可供端到端验证。

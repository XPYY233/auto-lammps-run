# 冻结输入与只读 Slurm 查询

PR 1b 是受信控制端内部模块。它不提交、不取消、不执行引擎，也没有作为主 Agent 的 SSH 工具开放。科学条件检查与系统身份隔离仍需实现。

## 输入快照

`auto_lammps.manifest.freeze` 只接受显式文件清单，角色为一个 `lammps_input`，以及必要的 `structure`、`potential`、`analysis_spec`。冻结文件内容、大小和 SHA-256，入口、资源申请，以及 task/analysis/software 三个版本摘要。任务与软件摘要指向的实际资料须由控制端保存；哈希本身不是科学条件或版本来源的证明。

使用按内容摘要命名的私人目录，拒绝 Git 工作树内存储，已有目录不覆盖。输入采用逐段不跟随链接的文件描述符读取，拒绝越界路径、符号链接、硬链接、FIFO 和非普通文件。文件在读取期间变化会失败。快照文件只读；每次后续使用前必须重新验证内容和清单，拒绝额外文件。输入和清单计入请求的存储额度，运行输出、日志与暂存副本还需在生产适配器中计入总量。

该功能不会解析或执行 LAMMPS。命令、元素映射、单位、势函数兼容性、初始结构和论文条件均未经过此模块核验。同一操作系统身份仍可改权限或存在检查后替换风险；正式运行必须由隔离的受信服务持有目录，并在传输及执行边界再次核对。不要将只读权限表述成不可篡改或盲测隔离。

## 只读查询

`auto_lammps.slurm_read.SlurmReader` 接受管理员配置的 SSH 别名和仓库之外的私人审计目录。复用现有 OpenSSH 身份配置，强制 BatchMode 和 StrictHostKeyChecking，关闭转发；调用端不能传入任意命令。当前仅生成固定 `squeue` 与 `sacct` 查询。查询有时间和输出上限；意图先落盘，原始 stdout/stderr、返回码、时间和摘要随后保存。任何审计写入失败都会向控制端报错。日志可能含私人集群信息，不得发布。

协议预留作业名 `al-<request_id>` 与 comment `al:<manifest_sha256>:<request_id>`。请求必须为 32 位小写十六进制，清单为 SHA-256。查询开始时间必须来自持久化提交意图，以明确 UTC 时间传入，不能只依赖默认当天范围。未来实际提交必须写入同样的标识；本 PR 尚未实现该写入端。

只有匹配名称与完整 comment 的普通单作业才解释状态。缺记录、空 comment、未知/截断状态、数组/异构作业、重复分配、重新排队和队列/历史冲突均保留 unknown。不会据此重提或释放额度。作业步骤不重复累加到根作业；无重排队的最终根分配记录可报告 `AllocCPUS × ElapsedRaw` 分配核秒。该值不是应用 CPU 使用时间，也不是科学成功。PR 1c 通过受信 [恢复服务](RECOVERY.md) 绑定持久请求并事务回写账本；该入口不执行提交。

Slurm 的 comment 保存依赖集群配置，且管理端可修改，不能把它作为针对恶意调度管理员的认证机制。参照官方 [squeue](https://slurm.schedmd.com/squeue.html) 与 [sacct](https://slurm.schedmd.com/sacct.html) 文档；`Restarts`、根作业/步骤区分及 comment 保存条件均以该接口为依据。

## 复用与验证

状态映射改编自既有 SIGA-LAMMPS `hpc/slurm.py`，固定提交 `dd2e0e7f7a7381ff8286fd1152ae1ee4958e319b`，保留 [MIT 声明](../third_party/SIGA-LAMMPS-LICENSE.txt)。旧连接层自动接受未知主机密钥，且没有满足当前要求的前置持久审计；此处采用固定命令的原生 OpenSSH 薄层，保留已有连接配置，不复制凭据或整个框架。TIMEOUT 单独保留；截断状态不自动扩展成终态。

离线测试覆盖内容冻结与损坏、目录与文件链接、存储额度、隐藏额外文件、私有权限、精确身份、缺失/截断输出、步骤计数、重新排队、超时、取消、冲突、审计失败阻止网络和真实子进程超时/输出上限。子进程仅为合成文本和休眠，不运行任何物理引擎。

指定入口上对随机无作业标识的真实只读探测已完成：两个查询均返回成功且空结果，解释为 unknown/not_visible，原始回执存于仓库之外。这只证明当前连接与查询参数兼容，不证明作业 comment 实际保存、计算节点依赖、取消、传输或真实作业恢复。没有提交、目标计算、模型调用或 P-A-B 结果。

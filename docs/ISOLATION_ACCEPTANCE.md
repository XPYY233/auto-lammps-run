# 正式盲测的隔离验收前置清单

本文件回答一个问题：**在启动一次正式盲测（B）之前，隔离必须先满足什么，以及如何证明它已满足。**

它不重复机制细节：沙箱与计算节点启动器见 [受信提交与计算节点启动器](RUNTIME.md)，
许可与上传/派发绑定见 [从候选方案到已有许可下的执行](AUTHORIZED_EXECUTION.md)，
评分与容差见 [科学评测规范](EVALUATION.md)（**当前未冻结**）。三者都被本清单引用，但都不能替代本清单的核验。

## 铁律

1. **隔离只能由操作系统机制强制**：身份、挂载、工具、网络四类约束必须落在内核可执行的配置上。
   **不得**用提示词、目录约定、"Agent 应该看不到"或"上下文里没有"作为隔离证据。
2. **"已配置"与"已验证"必须分开记录**：写出配置不等于跑通；配置与摘要存在，不等于某次真实运行中约束确实生效。
3. **任一层缺失即不得声称盲测隔离**，也不得开始 B。缺失时正确的动作是补齐或改为非盲测用途并如实标注。

## 五层前置清单

| 层 | 必须存在 | 证据 | 判定 | 失败样例 |
|---|---|---|---|---|
| **身份** | 控制端与执行端使用**不同 OS 身份**；执行端不继承控制端环境；凭据不进执行端 | 进程属主记录、`id` 输出、环境清理配置 | 执行进程的属主与凭据可达性均与控制端不同 | 执行进程以控制端身份运行，或可读到控制端 home 下的密钥 |
| **挂载** | `runtime.json` 中 `requests_root`、`control_root`、`runtime_tree` **互不包含**；不挂载宿主 home、控制目录、系统软件目录 | 冻结的 `runtime.json` 与其摘要；沙箱挂载清单 | 挂载集合等于声明集合，无额外可写挂载 | 为图方便额外挂载一个"只读"数据目录，或挂载宿主 home |
| **工具** | 运行树按 `runtime_files` **逐文件摘要**固定；`engine_relative` 指向声明的引擎；无解释器/编译器等逃逸口 | 清单摘要、逐文件校验回执 | 实际运行树的每个文件与清单一致 | 依赖系统 PATH 上的二进制，或用未列入清单的解释器 |
| **网络** | 沙箱内**外部网络断开**；MPI 传输仅 `none` 或 `intel-shm`，启动器取自 `mpi_launcher` 声明 | 沙箱配置、运行日志、传输声明 | 运行期无法访问沙箱外网络 | 为传文件临时开放网络，或用未声明的传输 |
| **输入与输出** | B 的输入清单**不含作者源码、作者日志、目标答案**；仅预声明文件可写；回收按摘要 | B 输入清单摘要、禁用项清单、输出清单 | 输入清单闭包等于允许集合；输出只出现在预声明路径 | 把作者参考目录一并挂入"方便对照"，或回收未声明文件 |

**关于输入层**：这一层是唯一无法仅靠内核配置表达的（"模型没看过"不是内核属性）。
因此它必须以**清单冻结 + 摘要**的形式留下可核验痕迹：允许读取的文件集合、禁用集合，
以及该轮 B 的身份（无历史上下文）说明；并且这几项必须与其它四层一起进入同一份冻结记录。

## 冻结记录

正式评测前，以下内容一并冻结为一份规范化 JSON（字段名示意，具体以实现为准）：

- `runtime_profile_sha256`：许可 profile 与运行配置的摘要（沿用"修改后旧许可失效"语义）；
- `runtime_files_manifest_sha256`：运行树逐文件清单摘要；
- `b_input_manifest_sha256`：B 允许输入清单摘要（含禁用集合）；
- `scoring_sha256`：评分口径与容差摘要（见下节前置）；
- `identity`：执行端身份与隔离层级声明；
- `frozen_at`：冻结时间。

**任何一项改变，整份记录作废**，必须重新冻结并重新出具许可；不得在旧记录上"打补丁"。

## 与评分冻结的衔接

[科学评测规范](EVALUATION.md) 目前标题即"未冻结"，因此**当前不具备启动 B 的评分前置**。
进入 B 之前至少要有：目标物理量清单、论文 P 值的**已核实来源**、比较方法（绝对/相对差、单位）、
容差及其依据、以及"何时判定科学通过"的规则；并同样进入冻结记录的 `scoring_sha256`。
容差**不得**用"数值接近"倒推，也不得用作者 demo 日志的数值代替论文 P 值。

## 三层结论必须分开记录

| 结论 | 含义 | 不得混淆为 |
|---|---|---|
| 调度完成 | 作业被集群接受并结束 | 不是输出有效，更不是科学通过 |
| 输出有效 | 预声明输出齐全、可解析、摘要一致 | 不是科学通过 |
| 科学通过 | 在冻结的评分口径与容差下判定通过 | 不得由前两层推导 |

沿用 [科学评测规范](EVALUATION.md) 的措辞：静态通过和调度完成均不是科学成功。

## 当前状态（截至 2026-09-28，如实记录）

**已有实现（机制层）**：`RUNTIME.md` 描述的 bwrap 隔离（namespace、断网、去 capability、新会话、不挂控制目录与宿主 home）、
`runtime.json` 的三类根互不包含与逐文件摘要清单、libseccomp 过滤器（禁 unshare/setns 等）、
`AUTHORIZED_EXECUTION.md` 的许可与账本绑定。

**尚未验证（阻塞 B）**：
1. **尚未做过一次真实的隔离验收运行**——上述机制没有以"某次运行中约束确实生效"的形式留过回执；
2. **B 输入清单未冻结**（允许/禁用集合尚未成为带摘要的记录）；
3. **评分规范未冻结**（`EVALUATION.md` 标题即为"未冻结"）；
4. 五层证据尚未汇总为**同一份**冻结记录。

因此当前**不得**声称任何一轮评测具备盲测隔离；第一周的对比结论按其既有记录保持
`diagnostic_comparison_not_formal_pass` 与 `formal_blind=false` 的定性，不回改。

## 验收步骤（待授权后执行）

1. 汇总五层证据到一份冻结记录草案，逐项标注"已实现/已验证/未验证"；
2. 以**非目标任务**做一次隔离验收运行：确认断网、挂载集合、逐文件摘要、身份与环境隔离均在运行期成立，并留回执；
3. 冻结评分口径与容差（另见 [科学评测规范](EVALUATION.md)），产出 `scoring_sha256`；
4. 冻结 B 输入清单（允许 + 禁用），产出 `b_input_manifest_sha256`；
5. 由控制端复核上述记录并签发许可；**在此之前不启动 B**。

**边界声明**：本清单是前置说明，不构成任何批准，也不证明隔离已经成立；它只规定"什么才算成立"以及"当前还差什么"。

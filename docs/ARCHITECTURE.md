# 架构决定

ADR-000：产品是自然语言科研计算服务；文献复现是验证产品的测试体系。研究入口无需论文，测试入口由文献工作台生成等价用户需求，二者共用主 Agent 与领域 Adapter。Adapter 对接结构、势函数、输入检查、HPC、输出和分析，不等同于模型 HTTP 连接器。已验证作者源码测试集库与运行势函数库分别管理，隐藏目标源码不能成为被测 Agent 的检索资源。

ADR-001：Python 轻量后端 + 浏览器 + 独立工作进程 + SQLite 持久化。关闭浏览器不取消任务；重启先恢复查询，不重新提交。当前有文献 CLI、提交账本、输入快照与只读调度查询；已有本机条件确认网页；尚无完成生产验收的计算 worker。

ADR-002：保留一个生成 Agent。参考端、生成端、评分器与改进角色通过系统权限隔离。目录分开不构成访问隔离；正式评测前必须验证用户身份、挂载、工具及网络允许列表。普通确定性操作使用程序；先内部接口，必要时再用官方 SDK 暴露真正 MCP 处理程序。

ADR-003：复用已有受控 SSH/SFTP 和 Slurm 模块的协议与可维护代码，先修正审计发现。不复制旧项目凭据、真实工作区或历史数据。旧 Claude/dsh 流程保留作基线，模型差异单列。领域操作：prepare_case、resolve_potential、validate_case、submit_case、get_job_status、fetch_outputs、analyze_outputs、cancel_job。模型永不获得任意终端或 SSH 权限。

ADR-004：任务字段逐项记录 value、unit、origin（user/paper/code/proposed/missing）、source_locator 和 confirmation。确认冻结后才能生成。缺失条件不自动补默认值。覆盖结构、材料、尺寸晶向、边界、缺陷/加载、势函数版本与元素映射、单位、温压、系综、时间步、阶段、种子、采样、输出、分析和资源预算。结果值不得充当输入。

ADR-005：论文代码索引与势函数索引分离。论文固定 DOI、仓库、提交、依赖与输入。势函数记录元素、格式、映射、单位、接入包、来源、许可、哈希、适用证据；状态为 collected/connected/task_verified。复现模式固定模型；开放研究选择须有依据及确认。

ADR-006：文献工作台通过有版本的证据格式适配。条目来源明确区分 lammps_direct/lammps_postprocessed/other/unresolved；每项关联正文、图注或补充材料位置。保留人工核对能力不等于以人工填写缺失科学数据。AI 不得补造数值、轨迹或条件。独立生成端不接收 P、A、作者目标脚本或专用分析源码。

ADR-007：模型提供方、协议、模型、能力、超时、重试、用量单独配置；无自动付费回退。先做批准的低成本能力验证；密钥仅服务端。轮询、哈希、解析和计分不调用模型。

阶段分工以用户最新澄清为准：第一周由 Codex 负责 P-A-B 真实流程验证，包括参考整理、执行编排和分析；第二周开始由独立 API 驱动模型决策，之后真实科研也使用独立 API。Codex 的第一周参与必须留痕，不作为独立 API 自动化验收证据。首次验证跑通后再索取 API 配置。进入 B 前须先汇报策略并获得用户确认，实际输入隔离与 HPC 记账要求不变。

ADR-008：界面使用新建计算、我的计算、文献与势函数、结果对比。显示真实阶段、更新时间、输入依据、提交次数和预算，不用编造百分比或倒计时。技术日志可展开。OVITO 按选中目标需要接入 Python 接口并核对许可；其桌面 Pro 许可不视为相同授权。

ADR-009：输入快照使用内容摘要和显式文件清单。只读 Slurm 查询复用现有 OpenSSH 配置，以严格主机认证、固定命令、输出/时间上限和前置审计替代旧连接层的自动信任行为。仅改编 MIT 状态映射；生产上传/提交和系统隔离后续接入，边界见 FROZEN_INPUTS.md。

ADR-010：任务确认使用 FastAPI、SQLite 修订历史和本地静态网页。原始描述与来源保留，明确标签行可确定性提取；任意自然语言不猜填。冻结审阅记录不构成科学验证、主 Agent 任务包或执行授权。前端不接收 HPC/模型凭据，见 TASKS.md。

ADR-011：失败经验须进入产品机制。领域 Adapter 负责可验证的工具契约、能力复用、条件检查与恢复；RAG 负责检索带来源、适用条件和验证状态的领域知识与经验。检索不能代替程序检查、科学核验或运行授权。参考答案库与被测 Agent 的检索权限分离；任务内固定版本，经验经开发集复验后进入后续版本。具体职责、反例和尚未实现项见 [失败经验与可靠性设计](RELIABILITY.md)。本决定不为当前 A 增加知识库建设前置条件。

ADR-012（用户修订，2026-10-07）：Adapter 是主动接入 AI 工作过程的科研工具与规则层。
它提供类似 MCP 的可执行工具能力和类似 Skill 的方法规范；应用根据当前阶段、冻结条件
与允许资源，自动提供版本化能力、约束和证据，再进行执行前检查、执行后产物核对及
具体反馈。失败时沿同一任务有界修订、复验，不等待模型自行记起或查找规范。
这一职责贯穿规划、结构、势函数、脚本、HPC、分析和可视化；不替代 AI 的科学决策、
独立授权/记账或 PAB 评分，不通过无限审核阻塞非致命建议。当前准备阶段接入与其他
阶段的待实现/待验收状态分开记录；文档、上下文注入或工具单测都不等于完整闭环通过。

## 2026-09-30 系统架构实现状态（用户端验收进行中）

模块存在、离线测试通过、真实用户端闭环是三个不同证据级别。第一周控制端 P–A–B 成功不替代第二周应用端验收。

| 图中模块 | 已有实现与证据入口 | 尚未完成的验收 |
|---|---|---|
| 用户界面 | 自然语言任务、条件/方案审阅、历史、文件、模型与 HPC 连接管理 | 原任务从条件到结果的完整可用性；减少逐项确认负担 |
| 任务调度与 Agent | research_workflow、candidate_jobs、execution_jobs；付费请求记账、候选摘要、审批及事件历史 | 实际任务全链路、恢复与失败后一次纠错 |
| 结构/势函数/脚本 Adapter | structures、potentials、agent_candidates；版本与来源固定；受限多结构阶段 | 任务范围仍受命令/结构能力约束，不能声称任意材料/方法已支持 |
| HPC | 受控部署、提交账本、Slurm 查询、输出回收 | 本次应用入口实际作业与终态核验；关浏览器仍持续监控的验收 |
| 分析与 OVITO | 数值表计划、运算及下载；已有 PAB 结构后处理 | 通用新任务自动选图、结构与动画分析的完整闭环 |

公开界面应按实际事件说明模型调用、工具动作、输入/输出、等待或失败原因。`prepared` 只表示产物通过当前契约；调度完成、输出有效、科学结论须分别记录。不得靠开发者私有提交补齐用户端流程后宣称自动化通过。

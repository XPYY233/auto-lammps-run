# 任务结果与运行历史

Issue #37 将已保存的回收、数值分析及提交账本接回同一科研任务页。
用户可以查看每轮提交次数、每次计算状态、数值与单位、来源行号、分析报告下载和运行历史。
这是一项读取功能；仍没有真实目标计算或科学通过记录。

## 关联与次数

任务冻结条件的摘要必须与准备记录一致。准备记录的输入快照摘要定位账本评测，只接收
`agent` 角色；作者参考、开发验证和独立分析角色不进入产品结果页。随后读取该评测的
全部请求，因此第二次修复即使使用新快照也不会丢失。评测之间分别计数，不混算成一个
任务总上限；准备/下载/分析不会算成计算提交。

`dispatch_claimed` 表示已经发起派发，失败或结果不明也计数；`prepared` 另显示为待提交
但占用一次额度。界面只反映账本，不提供重置或再次提交按钮。取消前未派发不计为已提交。
单次读取最多 64 组评测、每组 128 条请求、每请求 2000 条事件；超限明确拒绝，尚未分页。

这是本机操作人员的结果视图，不是正式盲测权限边界。运行身份、挂载及网络隔离仍须部署
验收；按角色过滤不能替代这些约束。

## 报告核验

每次读取核对报告字节与账本中不可覆盖的保存摘要，匹配分析预留、输入快照、作业和
报告目录身份，再核对对应回收回执摘要及其关联。账本必须仍为已结束且完成核算。
缺失、损坏、身份不符或调度状态矛盾时，不向网页或下载接口提供数值。分析失败保留失败
状态，不公开原始异常文本。

页面核验的是**保存报告及来源回执的完整性**，不会每次刷新重新读取全部轨迹、重新分析或
请求 HPC。原始数据当前是否仍完整，应通过回收/分析服务的完整复核判定；本视图不作这个
额外保证。下载仅包含当前任务通过核验的展示字段，不包括私人路径、原始日志、运行许可、
参考结果或算法运行环境。文件名、列、选中源行和源文件摘要用于追溯。

数值分析完成、调度结束与科学成功分别表示；当前科学状态始终为 `not_evaluated`。
没有将斜率自动命名为材料性质，没有 P-A-B 评分，也没有 OVITO 或结构图。已有数值分析
范围见 [ANALYSIS.md](ANALYSIS.md)。

## 配置与验证

本机网页服务增加三个联合配置项：已有 `--ledger`、`--collections-directory` 和
`--reports-directory`。两个结果目录须已经存在、位于 Git 外且仅本人可访问；不从网页
配置服务器路径。未配置时明确显示“结果服务尚未配置”。

GET `/api/tasks/{id}/results` 读取汇总；GET
`/api/tasks/{id}/results/{analysis_id}/download` 下载该任务的数值分析报告。
读取不会调用模型、调度器、SSH、回收或分析，不改变计数。页面打开时读取，可手动刷新；
尚未接入后台的主动通知。[自动跟进服务](FOLLOWING.md)保存的阶段事件已进入该历史视图。

验证包括真实本地子进程传输的合成表、实际分析报告、任务关联与跨任务下载拒绝、参考角色
排除、不同快照的第二次提交、未知提交计数、数据库重开、报告/回执变化以及调度矛盾。
首轮新增测试在合成准备函数中嵌套了两个写事务而锁住数据库；已改为事务前读取摘要并
重新通过。浏览器独立合成任务实测数值/单位、源行、运行历史、刷新、损坏报告隐藏数值；
未修改实际研究数据。没有模型 API、HPC 提交或目标模拟。
